# A3 v2：畫線層「分組」畫法（2026-10-24，gpui-opt2）

## 結論先講

- **預設維持關（全部走 path）。** 這台沒有顯示卡（軟體 Vulkan／llvmpipe），A3 v2 重圖表 FPS **20.8 → 10.3**，掉一半，跟 A3 v1（11.8）差不多。
- **截圖：上下順序是對的，但不是逐點相同。** 8 組隨機畫線，分組畫法和「一個一個照順序畫」比，只有 1 組完全一樣；其他組差 21～3358 個點，都是半透明線重疊處的鋸齒邊緣，每一塊差異最多 8 個點、亮度最多差 48／255。沒有整條線或整塊順序畫錯。
- **開關還在**：`XQ_DRAW_QUADS=1` 就是 A3 v2。請在 Windows（GTX 1650）和 Mac（M4）壓測包各跑一次開／關，有顯示卡時結果可能不同。
- 附帶發現：舊畫法（全 path）其實有順序錯誤，**文字一律蓋在所有線上面**，不管誰後畫。A3 v2 修好了這點，所以 A3 v2 跟舊畫法的截圖本來就會不一樣。

## 做了什麼

`src/drawings.rs`：

1. 水平線、垂直線、矩形邊框／填色、文字框改用 quad（方塊）畫；斜線、曲線、多邊形還是 path。
2. 依畫線的前後順序，把每個圖元放進「最早、又不會改變看到的上下關係」的 `paint_layer` 群組。
   - 同一組裡 GPUI 一定是 quad 先、path 再、文字最後。
   - path 蓋在較早的 quad 上：可以同組。quad 要蓋住較早又重疊的 path（或文字），就得開下一組。
   - 重疊判斷用「外框＋線寬＋1.5 px 反鋸齒邊」，用格子（spatial grid）查，只在畫線變動或縮放／平移時重算，不是每幀算。
3. 同一組裡同顏色的 path 合成一條。
4. 兩個 GPUI 的坑（只影響分組／逐一模式）：
   - 同一組內每條 path 各自合成，半透明的重疊處會被疊兩次 → 每組後面補一條透明的 1 px path，讓 GPUI 改用「整批一張」合成；文字另外一層。
   - path 合成範圍剛好等於頂點外框，反鋸齒邊會被切掉 1 px → 外框往外擴 1 px。

`XQ_DRAW_QUADS`：不設或 `0`＝全 path（預設）；`1`＝A3 v2 分組；`v1`＝A3 v1；`seq`＝每個圖元一層、逐一照順序畫（正確性參考，最慢）。

## 截圖比對（ztest/）

同一個程式、合成 K 棒、不連行情（`XQ_ZTEST=8`），每個 seed 依序切換 分組 → 逐一 → 全 path → 逐一，每次在 Xvfb 1600×1000 截圖，只比圖面（y < 850，狀態列 FPS 數字會跳）。seed 0 是重圖表情境（1000 筆畫線／100 層），其他是 30～150 筆隨機畫線、1～8 層隨機順序，seed 2、5 還選取一筆畫線。

| seed | 畫線／層 | 選取 | 圖元 | 群組 | 分組：path／path 批次 | 逐一：path 批次 | 全 path：path／批次 | 分組 vs 逐一：差異點／差>8／最大差 | 逐一 vs 逐一 |
|---|---|---|---|---|---|---|---|---|---|
| 0 | 1000／100 | 無 | 669 | 147 | 62／35 | 38 | 309／1 | 48／14／37 | 0 |
| 1 | 118／6 | 無 | 688 | 136 | 63／44 | 44 | 327／1 | 166／9／20 | 0 |
| 2 | 95／4 | 有 | 488 | 117 | 43／29 | 34 | 239／2 | 3358／39／36 | 0 |
| 3 | 129／8 | 無 | 526 | 111 | 66／37 | 40 | 241／1 | 21／9／20 | 0 |
| 4 | 41／6 | 無 | 187 | 29 | 12／7 | 8 | 74／1 | 40／3／48 | 0 |
| 5 | 45／2 | 有 | 273 | 65 | 15／10 | 14 | 141／2 | 0／0／0 | 0 |
| 6 | 63／8 | 無 | 317 | 80 | 30／18 | 19 | 162／1 | 212／12／32 | 0 |
| 7 | 80／3 | 無 | 491 | 103 | 41／27 | 29 | 245／1 | 230／28／45 | 0 |

- 「逐一 vs 逐一」都是 0：截圖流程本身穩定，差異不是雜訊。
- 差 >8 的點，連在一起最大的一塊：seed 0～7 分別 5、3、3、3、2、0、2、8 個點 → 只在邊緣，不是順序錯。
- 為什麼還差一點：GPUI 每一批 path 先在 MSAA 中介貼圖上畫、解析成一般像素再合成。分組會把原本分在兩批的 path 放進同一批，重疊邊緣的取樣混合方式就不同（同一批比較準）。要逐點相同，得讓兩邊的批次完全一樣，那就失去分組的意義。
- 群組數：重圖表 669 個圖元 → 147 組。path 數 309 → 62，但 **path 批次 1 → 35**；這就是變慢的原因。
- 重建一次：分組 1.5～3.2 ms，全 path 0.6～1.0 ms（只在畫線變動、縮放、平移、價格刻度變動時重建）。
- `ztest/s02-grouped.png`、`s02-seq.png` 是差最多的一組，可以自己疊圖看。

## 軟體繪圖 FPS（fps/）

`scripts/bench-main-window.sh 1 heavy`（主視窗、圖面 1166×505、20 個疊加＋8 副圖＋1000 筆畫線），同一個執行檔只換 `XQ_DRAW_QUADS`，三種輪流 3 輪（22:27–22:38 台北時間），中位數：

| 段落 | 全 path（0，預設） | A3 v2（1） | A3 v1（v1） |
|---|---|---|---|
| 跳價 FPS | 20.8 | 10.4 | 11.7 |
| 十字線 FPS | 20.8 | 10.3 | 11.8 |
| 平移 FPS | 20.8 | 9.9 | 12.3 |
| 拖曳 FPS | 20.8 | 10.1 | 12.2 |
| 十字線 CPU（含 llvmpipe，100%＝1 核） | 278% | 436% | 433% |
| 十字線每幀繪製（程式端） | 2.52 ms | 2.88 ms | 2.68 ms |

- 慢在 GPU 那一側（這台是 CPU 模擬的 llvmpipe）：每多一批 path，就多清一次、合成一次整窗的中介貼圖。程式端每幀只多約 0.4 ms。
- 3 輪都一樣方向，不是雜訊。這台另有 Android 模擬器吃約 2 顆核心，三種模式受影響一樣。
